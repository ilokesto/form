# Array fields

Dynamic lists need two paths: the array path and each child field path. Get stable render keys from `form.array(path).keys()` and use tuple paths for child fields.

```tsx lineNumbers
const phones = form.array(['phones']);
const keys = phones.keys();
const bindings = useRegister(keys.map((_, index) => ({
  name: ['phones', index, 'value'] as const,
})));

return keys.map((key, index) => (
  <input key={key} {...bindings[index]} />
));
```

This is a React component fragment with `form` and `useRegister` already available. Register the list in one hook call rather than calling a hook inside `map`. When the user adds, removes, moves, swaps, or replaces items, call the `FormArray` command rather than directly setting unrelated fields. That lets the core rebase `dirty`, `touched`, `modified`, focus state, and errors. The rendered key keeps React from reusing a DOM node for the wrong logical item while the path index still describes the current value location.

## Checklist

Before shipping, verify that labels and accessibility attributes live in your markup, schema errors are shown near fields and summarized when useful, tuple paths are used for nested values, and array commands are the only way dynamic list structure changes. This keeps the form predictable even as product requirements grow.
