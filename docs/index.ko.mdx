# Form

마크업을 직접 제어하면서 폼 값을 수집하고 검증해 제출하려면 `@ilokesto/form`을 사용하세요. 프레임워크와 분리된 컨트롤러와 React, Vue, Solid, Svelte용 작은 어댑터를 제공합니다. 입력 요소, 라벨, 레이아웃, 접근성은 애플리케이션이 결정하고, Form은 값, 상호작용 상태, 검증 오류, 제출 상태, 배열 항목의 안정적인 키를 일관되게 관리합니다.

## 설치

```package-install
@ilokesto/form
```

사용하는 프레임워크 피어 의존성도 함께 설치하세요. 예를 들면 `react`, `vue`, `solid-js`, `svelte` 중 하나입니다. 루트 진입점은 의도적으로 프레임워크를 가져오지 않습니다. 그래서 서버 유틸리티, 테스트, 공유 도메인 모듈에서도 UI 런타임 없이 폼 인스턴스를 만들 수 있습니다.

## 코어 동작 확인하기

```ts lineNumbers
import { CreateForm } from '@ilokesto/form';

const form = new CreateForm({
  defaultValues: {
    email: '',
    profile: { name: 'Ada' },
    tags: ['docs'],
  },
  validateOn: ['blur', 'submit'],
});

form.setValue('email', 'ada@example.com', { source: 'user' });
form.setValue(['profile', 'name'], 'Grace', { source: 'user' });

const values = form.getValues();
const email = form.getFieldState('email');

console.log(values);
console.log(email.dirty, email.modified);
```

예시를 실행하면 `profile.name: 'Grace'`가 포함된 갱신된 값이 출력되고, 이어서 `true true`가 출력됩니다. 이메일 값이 초기값과 다르고 사용자 입력으로 변경되었기 때문입니다. 이 코어 흐름에는 UI 프레임워크가 필요하지 않습니다.

가장 중요한 규칙은 경로 의미입니다. 문자열은 그대로 하나의 필드 이름입니다. 따라서 `'profile.name'`은 점으로 나뉘는 경로가 아니라 최상위 필드 하나입니다. 중첩 값을 가리키려면 `['profile', 'name']` 같은 튜플 경로를 사용하세요. 이 명시성 덕분에 실제 제품 데이터의 필드 이름에 점이 들어가도 의도하지 않은 분리가 일어나지 않습니다.

## 이 패키지가 하지 않는 일

- 특정 렌더러나 컴포넌트 모델에 묶이지 않습니다.
- 스키마 라이브러리가 아닙니다. Standard Schema v1의 `~standard.validate` 계약을 소비합니다.
- 폼 생성기가 아닙니다. 마크업, 레이아웃, 라벨, 접근성은 애플리케이션이 결정합니다.
- 전역 앱 상태 대체재가 아닙니다. 오래 유지되는 앱 상태는 상태 계층에 두고, Form은 필드 상호작용 상태에 집중하세요.
